# NGO Visitor Manager - Deployment & Handover Guide
**(1 Root Machine + 3 Assistant Machines)**

## 1. Prerequisites (All Machines)
Before starting, ensure the following on all 4 laptops/computers:
*   **Operating System**: Windows 10 or 11.
*   **Browser**: Google Chrome, Microsoft Edge, or Firefox (Latest version).
*   **Network**: A way to transfer files (Office WiFi, LAN, or a USB Drive).
*   **Software**: No special software needed for *running* the app (it runs in the browser).

---

## 2. Installation (Do this ONCE on the Main Computer)

You need to "build" the application once to create the files that will be distributed to all machines.

### Step 2.1: Build the App
1.  Open the project folder (`ngo-visitor-manager`).
2.  Right-click "Open in Terminal" or run PowerShell.
3.  Run: `npm install` (Wait for it to finish).
4.  Run: `npm run build`.
5.  **Result**: A folder named **`dist`** will be created. This folder contains the *entire* application.

### Step 2.2: Distribute the App
1.  Copy the **`dist`** folder.
2.  Paste it onto a **USB Drive** or a Shared Network Folder.
3.  Rename it to `NGO_App` for clarity.

---

## 3. Deployment & Activation

Perform these steps on each of the 4 machines using the `NGO_App` folder you just copied.

### Machine 1: The Root Machine (Main Office)
*   **Role**: Master Database. Aggregates data from all assistants.
1.  Copy `NGO_App` folder to `C:\NGO_App` (or Desktop).
2.  Open the folder and double-click **`index.html`**.
3.  On the **Activation Screen**:
    *   **Master Key**: `SSP-DEV1-2026-TEST`
    *   **Machine Name**: `Root-Server` (or "Main Office")
    *   **Role**: Select **Root Machine** 🔴
    *   Click **Activate**.
4.  **Done!** This machine is ready.

### Machines 2, 3, & 4: Assistant Machines (Field Workers)
*   **Role**: Data Collection. They collect data and send it to Root.
1.  Copy `NGO_App` folder to the laptop.
2.  Open the folder and double-click **`index.html`**.
3.  On the **Activation Screen**:
    *   **Master Key**: `SSP-DEV1-2026-TEST`
    *   **Machine Name**: `Assistant-1` (then `Assistant-2`, `Assistant-3`)
    *   **Role**: Select **Satellite Machine** 🟢
    *   Click **Activate**.
4.  **Repeat** for all 3 assistants.

## 4. Daily Workflow & Syncing

Since the machines are offline or separate, you will sync data using files (JSON).

### Part A: Assistants Collect Data
1.  Assistants (1, 2, 3) go to the field and enter Visitors/Interactions.
2.  **End of Day/Week**:
    *   Go to **Data / Sync** tab.
    *   Click **"Generate Export (.json)"**.
    *   A file named like `NGO_Sync_Assistant-1_2026-01-17.json` will download.
    *   **Transfer this file** to the Root Machine (via USB, Email, or Network Share).

### Part B: Root Machine Merges Data
1.  Open the App on **Root Machine**.
2.  Go to **Data / Sync** tab.
3.  In the "Import / Sync Data" section (bottom/right):
    *   Click the **Dropzone** area.
    *   Select the JSON file from Assistant 1.
    *   Review the preview statistics.
    *   Click **"Proceed with Import"**.
4.  **Result**: The Root Machine now has all visitors from Assistant 1.
5.  **Repeat** for Assistant 2 and 3.

### Part C: Updates to Assistants (Optional)
If the Root Machine has edited data (e.g., corrected phone numbers) that Assistants need:
1.  Export from Root.
2.  Import that file on Assistants.
*Note: Generally, data flows from Assistants -> Root.*

## 5. Troubleshooting

*   **"Logo Missing"**: Ensure `sewa-sankalp-logo.png` is inside the `assets` or root folder. (Ideally, it is bundled in the `dist` folder automatically during build).
*   **"Sync Failed"**: Ensure you are importing a `.json` file generated by *this* app version.
*   **"Browser blocks file"**: If opening `index.html` directly gives errors, Chrome may block local file access. 
    *   *Solution*: It's best to run a simple web server (like `http-server`) OR use the deployable `.exe` wrapper if available.
    *   *Simple Fix*: Create a shortcut to Chrome with `--allow-file-access-from-files` (advanced) if strictly offline.

## 7. Making it Easy: Desktop Shortcut & Auto-Start

To make it easy for non-technical staff to open the app:

### Option A: Create a Desktop Shortcut (Easiest)
1.  Go to the `NGO_App` folder.
2.  Right-click on **`index.html`** (or `start_app.bat` if provided).
3.  Select **"Send to"** > **"Desktop (create shortcut)"**.
4.  Go to your Desktop, rename the new icon to "Dnyani Mitra".
5.  *Now staff can just double-click this icon.*

### Option B: Auto-Start when Laptop turns on
If you want the app to open automatically every morning:
1.  Press `Windows Key + R` on your keyboard.
2.  Type `shell:startup` and press Enter.
3.  A folder will open.
4.  **Copy** the "Dnyani Mitra" shortcut you created in Option A.
5.  **Paste** it into this Startup folder.
6.  *Now the app will launch automatically when the computer restarts.*
